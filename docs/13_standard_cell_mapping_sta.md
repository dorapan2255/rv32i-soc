# Nangate45 标准单元映射与静态时序分析

## 1. 功能

`make synth-core`把RTL转换为Yosys通用逻辑门，用于检查可综合性和逻辑单元规模。
标准单元映射把这些通用门换成工艺库中存在
的门，例如 `NAND2_X1`、`MUX2_X1` 和 `DFF_X1`。Liberty 文件给出了这些单元的
逻辑功能、面积、输入负载和延迟模型，因此可以估算面积并执行静态时序分析（STA）。

分析使用Nangate45 typical corner。它适合教学和开源流程验证，但不是商业晶圆厂的
签核工艺库，所以结果应作为设计基线和相对比较依据。

## 2. 映射流程

`synth_core_nangate45.ys` 的主要步骤为：

1. 读取 Liberty 和全部 CPU RTL；
2. 以 `rv32i_core` 为顶层进行综合并展平层次；
3. 用 `dfflibmap` 将触发器映射为 `DFF_X1`；
4. 用 ABC 将组合逻辑映射到 Nangate45 单元；
5. 输出统计、Verilog 网表和 JSON 网表；
6. 清空 Yosys 内部设计并重新读取门级网表，确认交付网表本身可解析。

映射结果：

| 指标 | 结果 |
|---|---:|
| 标准单元总数 | 6186 |
| `DFF_X1` | 1024 |
| `MUX2_X1` | 1397 |
| 估算标准单元面积 | 11254.46 µm² |
| Yosys 网表检查 | 0 个问题 |

1024 个触发器由 31 个 32-bit 通用寄存器和 32-bit PC 组成，即
`31 × 32 + 32 = 1024`。`x0` 没有物理存储，因此没有额外的 32 个触发器。

## 3. SDC约束

SDC使用以下约束：

| 约束 | 数值 | 含义 |
|---|---:|---|
| 时钟周期 | 10 ns | 目标频率 100 MHz |
| 时钟不确定度 | 0.2 ns | 时钟抖动与实现误差预算 |
| 输入延迟 | 1 ns | 外部存储器或逻辑在周期开始后 1 ns 提供输入 |
| 输出延迟 | 1 ns | 给接收端逻辑保留 1 ns |
| 输出负载 | 10 fF | 估算外部连线和接收端输入电容 |
| 输入驱动 | `BUF_X1` | 避免假设理想、无限驱动能力的输入源 |

这些数值是分析约束，不是板级测量值。改变时钟周期或 I/O 环境后，
slack 也会改变。

## 4. STA结果

分析结果为：

```text
worst slack 4.208
tns 0.00
```

- **WNS（Worst Negative Slack）** 实际报告的是最差 slack。`+4.208 ns` 表示最慢
  路径仍比要求时间早 4.208 ns，满足 100 MHz setup 约束；
- **TNS（Total Negative Slack）** 是所有负 slack 的总和。`0 ns` 表示没有
  setup 违例；
- `MET` 表示该路径满足约束，`VIOLATED` 表示不满足。

最慢路径为：

```text
instruction[15] → 组合译码/选择/ALU 网络 → data_address[31]
```

数据在 4.592 ns 到达输出；扣除 1 ns 输出延迟和 0.2 ns 时钟不确定度后，要求时间
为 8.8 ns，因此 slack 为 `8.8 - 4.592 = 4.208 ns`。这说明关键路径与单周期核心的
指令译码和地址计算组合路径有关。报告中的单元名如 `_08051_` 是综合生成名，阅读时
应重点看起点、终点、经过的单元类型以及每级 delay。

由该约束线性反推，零 slack 对应的周期约为 5.79 ns，即约 173 MHz。不过这个数值
只能作为综合后理论上限，不能直接声称芯片能以该频率工作。

## 5. 结果边界

这是 **pre-layout STA**：时钟树为理想时钟，连线电容主要来自估算，尚无布局布线后
提取的寄生参数。分析顶层为CPU core，Instruction Memory、Data Memory、MMIO 和
UART 不在该次分析中。布局布线后使用布局布线后的网表和寄生参数再次执行 STA，
并检查 setup、hold、最大转换时间和最大负载。
