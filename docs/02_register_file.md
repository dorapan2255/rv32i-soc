# 寄存器堆：组合读与同步写

## 模块作用

RV32I 有 32 个通用寄存器，每个寄存器宽 32-bit。大多数指令需要同时读取两个
源寄存器 `rs1`、`rs2`，并可能将一个结果写回目的寄存器 `rd`，因此本模块包含
两个读端口和一个写端口。

```text
rs1_addr ──> 读端口 1 ──> rs1_data
rs2_addr ──> 读端口 2 ──> rs2_data

rd_addr + rd_data + write_enable ──> 写端口
                         clk ───────> 上升沿完成写入
```

地址宽度为 5-bit，因为 `2^5 = 32`，可以表示寄存器编号 0～31。

## 组合读取

读端口使用连续赋值：

```systemverilog
assign rs1_data = (rs1_addr == 5'd0) ? 32'b0 : registers[rs1_addr];
```

改变读取地址后，不需要等待时钟沿，输出会经过组合逻辑传播后更新。三目运算符
在这里对应一个选择器：地址为零时选择常数零，否则选择寄存器数组中的数据。

## 同步写入

写端口只在时钟上升沿执行：

```systemverilog
always_ff @(posedge clk) begin
    if (write_enable && (rd_addr != 5'd0))
        registers[rd_addr] <= rd_data;
end
```

`always_ff` 表示这段代码描述触发器。时序逻辑使用非阻塞赋值 `<=`，使状态更新
统一发生在当前仿真时间步的非阻塞赋值阶段，也与真实触发器在时钟沿更新的行为
更接近。

## x0 的特殊规则

RISC-V 规定 `x0` 永远读取为零，写入 `x0` 的操作必须被忽略。本模块从两处保证：

1. 读地址为零时直接输出 `32'b0`；
2. 只有 `rd_addr != 0` 时才允许写寄存器数组。

这比依赖 `registers[0]` 的初始值更可靠。

## 为什么没有清零复位

RISC-V 不保证 `x1`～`x31` 的上电值。程序应在读取普通寄存器前先写入有效值。
如果复位时清零整个寄存器堆，会为每一位状态引入复位需求，增加复位网络和实现
成本，也可能妨碍综合工具将寄存器堆映射为存储结构。

该实现保证`x0`为零，testbench只检查已经写入过的普通寄存器。仿真
开始时其他寄存器出现 `x` 属于预期现象，不代表设计错误。

## 验证信号

在 GTKWave 中加入 `clk`、`write_enable`、`rd_addr`、`rd_data`、`rs1_addr`、
`rs2_addr`、`rs1_data` 和 `rs2_data`。重点观察：

- `rd_data` 在时钟上升沿写入；
- 改变 `rs1_addr` 或 `rs2_addr` 后，读数据不需要等待下一时钟沿；
- 尝试写入 `x0` 后，读出结果仍然是零；
- `write_enable=0` 时，即使写地址和写数据有效，寄存器内容也不改变。
